# LaneKeep

ディスプレイ構成ごとに「どのアプリのウィンドウを、どの画面の、どこに、どの大きさで置くか」を覚えて、元の配置に戻す macOS のメニューバーアプリです。

- **ワンクリックで復元**：メニューバーの一覧から「復元」、またはワークスペースごとのショートカット（⌃⌥1、⌃⌥2…）
- **画面をつないだら自動で復元**：自宅やオフィスで外部モニターをつないだ瞬間に、その構成で保存した配置へ戻します
- **スリープ解除時の自動復元**（ワークスペースごとに選択）
- 足りない画面がある場合はメイン画面などへ寄せて配置し、結果を1行で知らせます

アプリ名は仕様書どおり仮のものです。

## 動作環境

| | |
| --- | --- |
| 実行 | macOS 14 Sonoma 以降 |
| ビルド | Xcode 16 以降（Xcode 16.0 と 26.3 でビルドを確認） |
| 権限 | アクセシビリティのみ |

App Sandbox はアクセシビリティ API で他アプリのウィンドウを動かすため無効にしています（App Store 配布は対象外、仕様書 §8）。

## ビルドと起動

### Xcode で

1. `LaneKeep.xcodeproj` を開きます（初回は依存パッケージ KeyboardShortcuts を自動で取得します）。
2. スキーム **LaneKeep** を選んで実行（⌘R）します。Dock にはアイコンが出ず、メニューバーに LaneKeep のアイコンが出ます。

### コマンドラインで

```sh
make run       # ビルドして起動（build/ に出力）
make install   # /Applications にコピーして起動
make test      # LaneKeepKit の単体テスト
make cli       # コマンドラインツール lanekeep をビルド
make snapshots # 全画面の見た目を PNG に書き出す（開発用）
```

### 署名とアクセシビリティの許可について（重要）

macOS はアクセシビリティの許可をアプリの署名ごとに覚えます。既定の「ローカルで実行するための署名（アドホック署名）」では、**ビルドし直すたびに別のアプリとみなされ、許可をやり直す必要があります**。

ビルドし直しても許可を保つには、自分の開発チームで署名します。

```sh
cp Config/Local.xcconfig.example Config/Local.xcconfig
# Config/Local.xcconfig の DEVELOPMENT_TEAM を自分のチーム ID に書き換える
```

`Local.xcconfig` は git の管理外です。許可の状態がおかしくなったときは `make reset-permission` で LaneKeep の許可を消してから、改めて許可してください。

バンドル ID は `Config/LaneKeep.xcconfig` の `PRODUCT_BUNDLE_IDENTIFIER`（既定 `io.github.enomoso-pm.LaneKeep`）で変えられます。

## 使い方

1. **初回起動**：権限の案内が出ます。「システム設定を開く」を押し、「プライバシーとセキュリティ」→「アクセシビリティ」で LaneKeep をオンにします。許可は1秒ごとに確認しているので、オンにすると自動で一覧に進みます。
2. **保存**：ウィンドウを並べてから、メニューの「今の配置を保存…」。名前と色を決め、配置図を見ながら不要なウィンドウのチェックを外して保存します。保存した瞬間の画面構成も一緒に記録されます。
3. **復元**：一覧の「復元」かショートカット。今つながっている構成と一致するワークスペースは青枠、足りない画面があるものには事前に注意書きが出ます。
4. **自動復元**：保存した構成の画面をつなぐと、自動復元がオンのワークスペースを復元します。一致するものが複数あれば最後に使ったものを選びます。メニュー上部の「つないだら自動で復元」が全体のスイッチです。
5. **設定**（メニューの歯車、または ⌘,）：ワークスペースごとの配置図とウィンドウ規則の表、自動復元の条件、ショートカット、「一般」（ログイン時に起動、メニューを開くショートカット、足りない画面の寄せ先）、「除外するアプリ」。
   - 名前は見出しを押すと変えられます。色とアイコン、ワークスペースの削除は見出し右の「…」から（サイドバーの右クリックでも削除できます）。
   - 表の行を選ぶと配置図の該当ウィンドウが強調されます。配置図のウィンドウを押しても選べます。
   - 「ウィンドウの目印」を設定すると、タイトルにその文字を含むウィンドウを優先して選びます（同じアプリで複数のウィンドウを使い分けるとき用）。行にポインタを合わせると出る「変更」から設定します。「閉じていたら」も行ごとに変えられます。
   - ショートカットはキーの表示を押すと変えられます（⌫ で削除）。
   - 「今の配置で上書き」で、今の位置と大きさで記録し直せます。

## コマンドラインツール `lanekeep`

開発の最初の段階（仕様書 §11 の1）として、ウィンドウの一覧と移動ができるツールを同梱しています。アプリと同じ `workspaces.json` を読み書きします。実行するターミナルにアクセシビリティの許可が必要です。

```sh
make cli
B=Packages/LaneKeepKit/.build/release/lanekeep
$B displays                                   # 接続中の画面と構成の署名
$B windows                                    # ウィンドウ一覧（アプリ、タイトル、位置、大きさ、所属画面）
$B move Safari --display 1 --frame 0,0,50%,100%   # Safari を1台目の画面の左半分へ
$B save 自宅デスク                             # 今の配置をワークスペースとして保存
$B workspaces                                 # 保存済みの一覧
$B restore 自宅デスク                          # 復元
```

`--json` を付けると `displays` と `windows` は JSON で出力します。

## データ

`~/Library/Application Support/LaneKeep/` に保存します。

- `workspaces.json` … ワークスペース（仕様書 §5 の構造。位置は可視領域に対する 0〜1 の割合）
- `preferences.json` … 全体の設定（自動復元のスイッチ、足りない画面の寄せ先、除外するアプリ）
- ショートカットは KeyboardShortcuts が UserDefaults に保存します

読めないファイルがあっても上書きせず、`workspaces.unreadable-日時.json` のように残してから起動します。

## 仕組み

```
LaneKeep.xcodeproj          アプリ本体（SwiftUI、MenuBarExtra）
LaneKeep/
  App/                      エントリポイント、AppDelegate
  Model/                    AppModel（状態と操作）、画面構成の監視、ショートカット、ログイン項目
  Views/                    ポップオーバー（一覧・保存・権限案内）、設定ウィンドウ、共通部品
  Support/                  メニューバーの開閉、設定ウィンドウ、メニューバーアイコン
  Assets.xcassets           アプリアイコン、デザイントークン（ライト／ダーク）
Packages/LaneKeepKit/
  Sources/LaneKeepCore      プラットフォーム非依存のロジック（Linux でもテスト可能）
  Sources/LaneKeepSystem    アクセシビリティ API、NSScreen、NSWorkspace
  Sources/LaneKeepCLI       コマンドラインツール lanekeep
  Tests/LaneKeepCoreTests   単体テスト（Swift Testing）
Config/                     Info.plist（LSUIElement）、エンタイトルメント、ビルド設定
Tools/generate_app_icon.py  アプリアイコンの生成スクリプト
```

- **座標変換**（§6.5）：AppKit（左下原点）とアクセシビリティ（左上原点）の変換は `CoordinateConverter.flip` の1か所にまとめ、`axY = mainScreenHeight - (nsY + height)` を単体テストで確認しています。
- **画面の識別**（§6.2）：`CGDisplayCreateUUIDFromDisplayID` の UUID を使います。シリアル番号のない同型モニターが同じ UUID を返す場合は、左から順に `#2`、`#3` を付けて区別します。
- **構成変化の検知**：`didChangeScreenParametersNotification` と `NSWorkspace.didWakeNotification` を受け、最後の通知から2秒待ってから1回だけ判定します。解像度の変更など、署名が変わらない通知では復元しません。
- **復元の手順**（§6.4）：閉じているアプリを起動 → ウィンドウが現れるまで最大10秒（250ms 間隔）待つ → 最小化を解除 → 大きさ → 位置 → 大きさ の順で設定 → 実際の位置を読み直して結果に反映、の順です。起動に時間がかかるアプリを待つあいだも、ほかのアプリのウィンドウは先に配置します。アプリが大きさを丸めた場合は画面からはみ出さないよう位置を詰めます（§6.6）。
- 復元の処理は `WindowSystem` プロトコル越しに OS を操作するので、偽の環境を使って単体テストしています。

## 仕様にない細部で決めたこと

- **ウィンドウの目印**：目印（タイトルに含む文字）を設定した規則は、該当するウィンドウがなければ別のウィンドウで代用しません。目印がない規則は保存時の順番のウィンドウを使い、なければ空いている最初のウィンドウを使います。
- **閉じたアプリの扱い**：「閉じていたら起動する」規則は、アプリが終了していれば起動します。起動中でもウィンドウが1つもない場合（ウィンドウだけ閉じた場合）は、Dock アイコンを押したときと同じように開き直しを頼みます。ただし、どこかにウィンドウが残っているアプリは開き直しません。別のデスクトップにあるウィンドウへ画面ごと切り替わってしまうのを避けるためです。このため、閉じたウィンドウを裏で隠しておくだけのアプリ（一部のチャットアプリなど）は「見つかりませんでした」となります。Dock から開いてから復元してください。
- **画面の色**：内蔵ディスプレイはどのワークスペースでも常にオレンジ、メインの外部ディスプレイは青、3台目以降はグレーです（モックの「ノートPCのみ」と同じ）。
- **保存データ**：仕様書 §5 の構造に、表示用の項目（ウィンドウ規則の ID、画面の `isBuiltin` と `visibleFrame`）を加えています。古い形式や手で書いたファイルも、足りない項目を既定値で補って読み込みます。
- **足りない画面の寄せ先**：「メイン画面」（既定）、「いちばん大きい画面」、「寄せずにそのまま」から選べます。
- **ショートカットの重複**：あるショートカットを別の操作に割り当てると、元の操作からは外して、そのことを表示します。
- 保存・復元の結果は VoiceOver でも読み上げます。

## 既知の制約

仕様書 §6.1、§10 のとおりです。

- 別のデスクトップ（Space）にあるウィンドウは多くのアプリで取得できず、別のデスクトップへ移すこともできません。保存は今見えている画面で行ってください。
- フルスクリーンのウィンドウは対象外です。
- ウィンドウ情報を公開しないアプリは保存・復元できません。
- LaneKeep が起動していないあいだは自動復元は動きません（「一般」の「ログイン時に起動」をおすすめします）。
