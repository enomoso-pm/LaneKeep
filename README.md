# LaneKeep

ディスプレイ構成ごとに「どのアプリのウィンドウを、どの画面の、どこに、どの大きさで置くか」を覚えて、元の配置に戻す macOS のメニューバーアプリです。

- **ワンクリックで復元**：メニューバーの一覧から「復元」、またはワークスペースごとのショートカット（⌃⌥1、⌃⌥2…）
- **画面をつないだら自動で復元**：自宅やオフィスで外部モニターをつないだ瞬間に、その構成で保存した配置へ戻します
- **スリープ解除時の自動復元**（ワークスペースごとに選択）
- 足りない画面がある場合はメイン画面などへ寄せて配置し、結果を1行で知らせます

## ダウンロード

[Releases](https://github.com/enomoso-pm/LaneKeep/releases/latest) から `LaneKeep_<版>_universal.dmg` を落として開き、LaneKeep を「アプリケーション」へドラッグします。macOS 14 以降の、Apple シリコンと Intel の Mac で動きます。

Apple の公証を受けていないので、初めて開くときだけ macOS の確かめが要ります。macOS 15 以降では、警告が出たら「完了」を押し（青い「ゴミ箱に入れる」は押さないでください）、「システム設定」→「プライバシーとセキュリティ」のいちばん下で「このまま開く」を押します。macOS 14 では、Finder で LaneKeep を右クリック →「開く」です。手順は、.dmg を開いたときの窓（画面の絵つき）と、中の「はじめに読む.txt」にあります。

## 動作環境

| | |
| --- | --- |
| 実行 | macOS 14 Sonoma 以降 |

App Sandbox はアクセシビリティ API で他アプリのウィンドウを動かすため無効にしています（App Store 配布は対象外、仕様書 §8）。

## ビルドと起動

### Xcode で

1. `LaneKeep.xcodeproj` を開きます（初回は依存パッケージ KeyboardShortcuts を自動で取得します）。
2. スキーム **LaneKeep** を選んで実行（⌘R）します。Dock にはアイコンが出ず、メニューバーに LaneKeep のアイコンが出ます。

### コマンドラインで

```sh
make run       # ビルドして起動（build/ に出力）
make install   # /Applications にコピーして起動
make test      # LaneKeepKit の単体テスト
make cli       # コマンドラインツール lanekeep をビルド
make snapshots # 全画面の見た目を PNG に書き出す（開発用）
```

### Xcode なしで

Xcode の無い Mac でも、コマンドラインツールだけで、アプリと配る .dmg を作れます（自作の証明書で署名し、Apple シリコンと Intel の両方入り）。手順は [Tools/release/README.md](Tools/release/README.md) にあります。

### 署名とアクセシビリティの許可について（重要）

macOS はアクセシビリティの許可をアプリの署名ごとに覚えます。既定の「ローカルで実行するための署名（アドホック署名）」では、**ビルドし直すたびに別のアプリとみなされ、許可をやり直す必要があります**。

ビルドし直しても許可を保つには、自分の開発チームで署名します。

```sh
cp Config/Local.xcconfig.example Config/Local.xcconfig
# Config/Local.xcconfig の DEVELOPMENT_TEAM を自分のチーム ID に書き換える
```

`Local.xcconfig` は git の管理外です。許可の状態がおかしくなったときは `make reset-permission` で LaneKeep の許可を消してから、改めて許可してください。

バンドル ID は `Config/LaneKeep.xcconfig` の `PRODUCT_BUNDLE_IDENTIFIER`（既定 `io.github.enomoso-pm.LaneKeep`）で変えられます。

## 使い方

1. **初回起動**：権限の案内が出ます。「システム設定を開く」を押し、「プライバシーとセキュリティ」→「アクセシビリティ」で LaneKeep をオンにします。許可は1秒ごとに確認しているので、オンにすると自動で一覧に進みます。
2. **保存**：ウィンドウを並べてから、メニューの「今の配置を保存…」。名前と色を決め、配置図を見ながら不要なウィンドウのチェックを外して保存します。保存した瞬間の画面構成も一緒に記録されます。
3. **復元**：一覧の「復元」かショートカット。今つながっている構成と一致するワークスペースは青枠、足りない画面があるものには事前に注意書きが出ます。
4. **自動復元**：保存した構成の画面をつなぐと、自動復元がオンのワークスペースを復元します。一致するものが複数あれば最後に使ったものを選びます。メニュー上部の「つないだら自動で復元」が全体のスイッチです。
5. **設定**（メニューの歯車、または ⌘,）：ワークスペースごとの配置図とウィンドウ規則の表、自動復元の条件、ショートカット、「一般」（ログイン時に起動、メニューを開くショートカット、足りない画面の寄せ先）、「除外するアプリ」。
   - 名前は見出しを押すと変えられます。色とアイコン、ワークスペースの削除は見出し右の「…」から（サイドバーの右クリックでも削除できます）。
   - 表の行を選ぶと配置図の該当ウィンドウが強調されます。配置図のウィンドウを押しても選べます。
   - 「ウィンドウの目印」を設定すると、タイトルにその文字を含むウィンドウを優先して選びます（同じアプリで複数のウィンドウを使い分けるとき用）。行にポインタを合わせると出る「変更」から設定します。「閉じていたら」も行ごとに変えられます。
   - ショートカットはキーの表示を押すと変えられます（⌫ で削除）。
   - 「今の配置で上書き」で、今の位置と大きさで記録し直せます。

## コマンドラインツール `lanekeep`

開発の最初の段階（仕様書 §11 の1）として、ウィンドウの一覧と移動ができるツールを同梱しています。アプリと同じ `workspaces.json` を読み書きします。実行するターミナルにアクセシビリティの許可が必要です。

```sh
make cli
B=Packages/LaneKeepKit/.build/release/lanekeep
$B displays                                   # 接続中の画面と構成の署名
$B windows                                    # ウィンドウ一覧（アプリ、#番号、タイトル、位置、大きさ、所属画面）
$B move Safari --display 1 --frame 0,0,50%,100%   # Safari を1台目の画面の左半分へ
$B move ターミナル --index 1 --frame 50%,0,50%,100%  # ターミナルの #1 のウィンドウを右半分へ
$B save 自宅デスク                             # 今の配置をワークスペースとして保存
$B save 自宅デスク --replace                   # 同じ名前のワークスペースを今の配置で上書き
$B workspaces                                 # 保存済みの一覧
$B restore 自宅デスク                          # 名前（または workspaces の番号）で復元
```

- `--json` を付けると `displays` と `windows` は JSON で出力します。
- `--frame` は可視領域に対する割合です。画面からはみ出す値や、% の付け忘れ（`0,0,50,100`）はエラーになります。
- アプリの起動中に `save` した内容は、次にアプリのメニューを開いたときに一覧に出ます（アプリは自分が書いたあとにファイルが変わったことに気づくと、読み直して自分の変更とまとめます）。
- 読めない部分がある `workspaces.json` には書き込みません（ファイルにも手を付けません）。

## データ

`~/Library/Application Support/LaneKeep/` に保存します。

- `workspaces.json` … ワークスペース（仕様書 §5 の構造。位置は可視領域に対する 0〜1 の割合）
- `preferences.json` … 全体の設定（自動復元のスイッチ、足りない画面の寄せ先、除外するアプリ）
- ショートカットは KeyboardShortcuts が UserDefaults に保存します

読めないファイルがあっても上書きせず、`workspaces.unreadable-日時.json` のように残してから起動します。

## 仕組み

```
LaneKeep.xcodeproj          アプリ本体（SwiftUI、MenuBarExtra）
LaneKeep/
  App/                      エントリポイント、AppDelegate
  Model/                    AppModel（状態と操作）、画面構成の監視、ショートカット、ログイン項目
  Views/                    ポップオーバー（一覧・保存・権限案内）、設定ウィンドウ、共通部品
  Support/                  メニューバーの開閉、設定ウィンドウ、メニューバーアイコン
  Assets.xcassets           アプリアイコン、デザイントークン（ライト／ダーク）
Packages/LaneKeepKit/
  Sources/LaneKeepCore      プラットフォーム非依存のロジック（Linux でもテスト可能）
  Sources/LaneKeepSystem    アクセシビリティ API、NSScreen、NSWorkspace
  Sources/LaneKeepCLI       コマンドラインツール lanekeep
  Tests/LaneKeepCoreTests   単体テスト（Swift Testing）
Config/                     Info.plist（LSUIElement）、エンタイトルメント、ビルド設定
Tools/generate_app_icon.py  アプリアイコンの生成スクリプト
Tools/release/              Xcode なしでアプリと配る .dmg を作る手順
```

- **座標変換**（§6.5）：AppKit（左下原点）とアクセシビリティ（左上原点）の変換は `CoordinateConverter.flip` の1か所にまとめ、`axY = mainScreenHeight - (nsY + height)` を単体テストで確認しています。
- **画面の識別**（§6.2）：`CGDisplayCreateUUIDFromDisplayID` の UUID を使います。シリアル番号のない同型モニターが同じ UUID を返す場合は、左から順に `#2`、`#3` を付けて区別します。
- **画面構成の署名**：外部ディスプレイが1台以上あるときは、内蔵ディスプレイを除いた UUID で作ります（仕様書 §6.2 からの変更）。ふたを開けて保存したワークスペースが、ふたを閉じて同じモニターにつないだときにも一致するようにするためです。内蔵ディスプレイしかないときは内蔵の UUID が署名になります。署名を作る関数は `DisplaySignature.make(for:)` の1つだけで、古い形式の署名を持つ `workspaces.json` は読み込むときに作り直します。
- **構成変化の検知**：`didChangeScreenParametersNotification` に加えて、スリープ明けなどで通知が来ない場合に備え、Quartz のディスプレイ再構成コールバック（`CGDisplayRegisterReconfigurationCallback`、変更前の呼び出しは無視）、`NSWorkspace.screensDidWakeNotification`、1.5秒ごとの署名の確認（変わったときだけ動く）も使います。どこから来ても同じ経路を通り、最後の合図から2秒待ってから1回だけ判定するので、同じ変化で二重に復元することはありません。解像度の変更など、署名が変わらない通知では復元しません。スリープ解除（`NSWorkspace.didWakeNotification`）は「スリープ解除のとき」の判定に使います。
- **復元の手順**（§6.4）：閉じているアプリを起動 → ウィンドウが現れるまで最大10秒（250ms 間隔）待つ → 最小化を解除 → 大きさ → 位置 → 大きさ の順で設定 → 実際の位置を読み直して結果に反映、の順です。起動に時間がかかるアプリを待つあいだも、ほかのアプリのウィンドウは先に配置します。大きさが指定と違うときは、反応の遅いアプリのために少し待ってからもう一度設定し、2回目も同じ大きさならアプリが受け付けないとみなして、画面からはみ出さないよう位置を詰めます（§6.6）。
- **自動復元のあとの見直し**：モニターをつないだ直後の macOS は数秒間ウィンドウを動かし続けるので、自動復元が終わってから2.5秒後に1回だけ、その復元で置いたウィンドウを見直します。置いた位置から2pt 以上ずれたものだけ大きさと位置を設定し直し、閉じられたウィンドウやしまわれたウィンドウは飛ばします（アプリの起動や再オープンはしません）。そのあいだに別の復元が始まったとき、「つないだら自動で復元」がオフになったとき、画面構成が変わったとき（モニターを外した、ふたを閉じた、解像度や配置を変えた）は中止し、動かしている途中のウィンドウもそれ以上動かしません。見直しを始める直前にも、つながっているディスプレイとその位置・大きさ、メインディスプレイが復元したときと同じかを確かめ、違えば何もしません。この確認には署名を使いません（モニターをつないだままふたを閉じても署名は変わらないため）。Dock が別のディスプレイに移っただけなら中止せず、いまの使える範囲に置き直します。直した件数は結果の1行に「あとから動いたN件を置き直しました」と書き足します。手動の復元では見直しません。
- 復元の処理は `WindowSystem` プロトコル越しに OS を操作するので、偽の環境を使って単体テストしています。

## 仕様にない細部で決めたこと

- **ウィンドウの目印**：目印（タイトルに含む文字）を設定した規則は、該当するウィンドウがなければ別のウィンドウで代用しません。
- **同じアプリの複数のウィンドウ**：アクセシビリティ API はアプリのウィンドウを前面にあるものから順に返すので、「保存時の順番」（仕様書 §6.3 の index）はウィンドウをクリックするたびに入れ替わります。順番だけで選ぶと、ターミナルの左右のウィンドウが復元のたびに入れ替わってしまいます。そこで目印のない規則は、保存した位置と大きさにいちばん近いウィンドウ（画面に対する割合で比べ、同じ画面にあるものを優先）を選び、差がないときだけ保存時の順番を使います。どのウィンドウか決めておきたいときは目印を設定してください。
- **起動中のアプリのウィンドウ**：起動直後のアプリはウィンドウが1枚ずつ現れ、タイトルも遅れて付くので、目印のない規則はウィンドウの数とタイトルが落ち着くのを待ってから選びます（目印の規則が先にウィンドウを取れるように）。
- **応答しないアプリ**：画面構成の変化直後などでアプリが応答しない（アクセシビリティの呼び出しが1秒でタイムアウトする）ときは、ウィンドウがないとは判断せず、最大10秒まで聞き直します。それでも応答がなければ「…が応答しませんでした」と表示します。
- **閉じたアプリの扱い**：「閉じていたら起動する」規則は、アプリが終了していれば起動します。起動中でもウィンドウが1つもない場合（ウィンドウだけ閉じた場合）は、Dock アイコンを押したときと同じように開き直しを頼みます。ただし、別のデスクトップにウィンドウを開いているアプリは開き直しません。そのデスクトップへ画面ごと切り替わってしまうのを避けるためです。閉じたウィンドウを裏で隠しておくだけのアプリ（LINE など）は、隠れているウィンドウを数えずに開き直しを頼みます。ウィンドウが表示されているかどうかは macOS の公開されていない関数（SkyLight の `SLSWindowIsOrderedIn`）で調べます。使えない macOS では以前どおり、どこかにウィンドウが残っているアプリは開き直さず「見つかりませんでした」となるので、Dock から開いてから復元してください。
- **画面の色**：内蔵ディスプレイはどのワークスペースでも常にオレンジ、メインの外部ディスプレイは青、3台目以降はグレーです（モックの「ノートPCのみ」と同じ）。
- **はみ出したウィンドウ**：保存時に画面の端からはみ出していたウィンドウは、画面の内側に収めた位置で記録します（割合を 0〜1 に保つため）。
- **一瞬だけ外れた画面**：ケーブルの接触や KVM の切り替えで画面が2秒以内に外れて戻った場合も、macOS はその画面のウィンドウを別の画面へ移してしまうので、「つないだ」とみなして自動復元します。
- **自分で選んだ復元が優先**：画面をつないでから自動復元が始まるまで（2秒）のあいだに自分で別のワークスペースを復元した場合、その構成では自動復元をしません。また「つないだら自動で復元」をオフにすると、実行中の自動復元も止めます。
- **画面名の並び**：「内蔵ディスプレイ ＋ 外部 27インチ」のように、画面の並び（左から右）の順に表示します。
- **保存データ**：仕様書 §5 の構造に、表示用の項目（ウィンドウ規則の ID、画面の `isBuiltin` と `visibleFrame`）を加えています。古い形式や手で書いたファイルも、足りない項目を既定値で補って読み込みます。
- **足りない画面の寄せ先**：「メイン画面」（既定）、「いちばん大きい画面」、「寄せずにそのまま」から選べます。
- **ショートカットの重複**：あるショートカットを別の操作に割り当てると、元の操作からは外して、そのことを表示します。
- 保存・復元の結果は VoiceOver でも読み上げます。

## 既知の制約

仕様書 §6.1、§10 のとおりです。

- このリポジトリの検証は、単体テスト（座標変換、照合、復元の手順を偽の環境で、自動復元の判定、保存形式など）と、macOS 上でのビルドと画面の描画（CI）までです。実際のウィンドウ移動、画面の抜き差し、スリープ解除は、仕様書 §11 のとおり実機で確認してください。

- 別のデスクトップ（Space）にあるウィンドウは多くのアプリで取得できず、別のデスクトップへ移すこともできません。保存は今見えている画面で行ってください。
- フルスクリーンのウィンドウは対象外です。
- ウィンドウ情報を公開しないアプリは保存・復元できません。
- LaneKeep が起動していないあいだは自動復元は動きません（「一般」の「ログイン時に起動」をおすすめします）。
